PASO 1 — INICIALIZACIÓN DEL PROYECTO Y DEPENDENCIAS
────────────────────────────────────────────────────────────────────────────────

1.1 — Crear el proyecto Vite con template React + TypeScript
---------------------------------------------------------------
  npm create vite@latest biopatternsg-ui -- --template react-ts
  cd biopatternsg-ui
  npm install

1.2 — Instalar Tailwind CSS v3 + PostCSS + Autoprefixer
---------------------------------------------------------------
  npm install -D tailwindcss@3 postcss autoprefixer
  npx tailwindcss init -p --ts
    (genera: tailwind.config.ts y postcss.config.js)

1.3 — Instalar librerías de UI y utilidades
---------------------------------------------------------------
  npm install lucide-react class-variance-authority clsx tailwind-merge

  # Radix UI primitives (base manual de Shadcn UI)
  npm install @radix-ui/react-slot \
               @radix-ui/react-label \
               @radix-ui/react-checkbox \
               @radix-ui/react-dialog \
               @radix-ui/react-dropdown-menu \
               @radix-ui/react-navigation-menu \
               @radix-ui/react-form

  # Tipos de Node para vite.config.ts
  npm install -D @types/node

NOTA SOBRE SHADCN UI:
  En este proyecto se instalaron los primitivos de Radix UI manualmente y se
  codificaron los componentes de Shadcn UI directamente en la estructura
  Atomic Design. Esto es equivalente a ejecutar:
    npx shadcn-ui@latest init
    npx shadcn-ui@latest add button input label card form
  ...pero con clasificación manual en atoms/molecules/organisms en lugar de
  la carpeta genérica components/ui/.

  Si se prefiere usar el CLI de Shadcn, ejecutar:
    npx shadcn-ui@latest init
  Y luego mover los archivos generados en src/components/ui/ a:
    src/components/atoms/    → Button, Input, Label
    src/components/molecules/ → Card, FormField
    src/components/organisms/ → LoginForm

1.5 — Configurar alias de rutas en vite.config.ts y tsconfig.app.json
---------------------------------------------------------------
  vite.config.ts:
    resolve: { alias: { "@": path.resolve(__dirname, "./src") } }

  tsconfig.app.json (dentro de compilerOptions):
    "baseUrl": ".",
    "paths": { "@/*": ["./src/*"] },
    "ignoreDeprecations": "6.0"

1.6 — Crear src/lib/utils.ts (helper cn para Tailwind Merge)
---------------------------------------------------------------
  import { clsx, type ClassValue } from "clsx";
  import { twMerge } from "tailwind-merge";
  export function cn(...inputs: ClassValue[]) {
    return twMerge(clsx(inputs));
  }

────────────────────────────────────────────────────────────────────────────────

ARCHIVO: tailwind.config.ts

  - content: ["./index.html", "./src/**/*.{ts,tsx,js,jsx}"]
  - Colores Brand: primary (#0050cb), primary-container (#0066ff),

  - Superficies (Tonal Architecture):

  - Tokens extraídos del HTML original (sistema Material Color):

  - Fuentes: headline/body → Inter, label → Space Grotesk

  - Sombras ambientales teñidas con #0d1c2e (NO sombras grises):
      shadow-sm, shadow-md, shadow-lg, shadow-xl, shadow-primary-glow, shadow-nav

ARCHIVO: src/index.css
  - Import de Google Fonts (Inter + Space Grotesk)
  - @tailwind base / components / utilities
  - CSS Custom Properties (variables Shadcn UI bridge):
      --background, --foreground, --primary, --secondary, --muted,
      --accent, --border, --input, --ring, --radius, etc.
  - Variables dark mode bajo .dark {}
  - Base reset: html → font-feature-settings, -webkit-font-smoothing
  - ::selection con primary-fixed / on-primary-fixed
  - Scrollbar personalizado (width 6px, track #f4f2fd, thumb #ccc3d8)
  - Utilidades @layer utilities:
      .pulse-gradient  → linear-gradient(135deg, #0066FF, #0052cc)
      .glass-panel     → rgba(255,255,255,0.8) + backdrop-blur(20px)
      .glass-nav       → rgba(251,248,255,0.80) + backdrop-blur(20px)
      .ghost-border    → outline 1px rgba(204,195,216,0.15) [regla No-Line]
      .shadow-ambient  → box-shadow teñida con #0d1c2e
      .shadow-primary-glow → box-shadow azul primario

REGLAS DE DISEÑO APLICADAS:
  - "No-Line" Rule: PROHIBIDO border de 1px para separar secciones/cards.
    Se usa diferencia de color de fondo (bg-surface vs bg-surface-container-low)
    o ghost-border (outline-variant al 15%) si es estrictamente necesario.
  - "Glass & Gradient" Rule: botones primarios usan pulse-gradient.
    Navbar y modales usan backdrop-blur-xl + fondo semi-transparente.
  - Tipografía: exclusivamente Inter (headline/body), Space Grotesk (label).
    Headings: tracking-tighter (-0.02em).
  - Sombras: solo sombras personalizadas teñidas, nunca grises de Tailwind.

PASO 5 — VISTA DE REGISTRO (modules/authenticator/register)
────────────────────────────────────────────────────────────────────────────────

5.1 — Instalar dependencias adicionales de navegación y validación
-----------------------------------------------------------------
  # Router de React
  npm install react-router-dom

  # Formularios y validaciones tipadas
  npm install react-hook-form zod @hookform/resolvers

5.2 — Configurar variable de entorno para URL base del API
-----------------------------------------------------------------
  Crear un archivo `.env` en la raíz del proyecto para definir la URL del API:
    VITE_API_URL=http://localhost:8080

  También se crea un `.env.example` como plantilla para control de versiones.
  Nota: Las variables en Vite deben empezar por VITE_ para exponerse al cliente.

5.3 — Constantes de URL y endpoints divididos en 2 partes
-----------------------------------------------------------------
  En `src/services/apiConfig.ts`:
  - Parte 1: URL base como constante principal `CONFIG_AND_CONTROL` (de .env)
  - Parte 2: Path del recurso como constante de ruta `REGISTER_PATH` ("api/config-and-control/users")
  - Se concatenan dinámicamente en: `USERS_ENDPOINT = `${CONFIG_AND_CONTROL}/${REGISTER_PATH}``

5.4 — Nuevos archivos de la arquitectura del registro
-----------------------------------------------------------------
  DOMAIN:
    · src/domain/models/User.ts: Define interfaces RegisterPayload y User.
  SERVICES:
    · src/services/apiConfig.ts: Configuración de constantes del API.
    · src/services/userService.ts: Función `registerUser` que hace Fetch POST.
  ADAPTERS:
    · src/adapters/userAdapter.ts: Adapta inputs de formulario a payloads del API.
  ATOMS:
    · src/components/atoms/SuccessModal.tsx: Modal custom con fondo glass-panel,
      backdrop blur, ícono CheckCircle, y controles de cierre (back, Esc, clic).
  MOLECULES:
    · src/components/molecules/RegisterFormFields.tsx: Estructura Email (Full),
      FirstName y LastName (2 columnas), y Password (Full) con sus errores.
  ORGANISMS:
    · src/components/organisms/RegisterForm.tsx: Form completo con resolver Zod,
      mensajes de error locales y API, animaciones y modal de éxito integrado.
  MODULES:
    · src/modules/authenticator/register/Register.tsx: Módulo completo (vista)
      que acopla Header, RegisterForm centrado sobre bg-surface-section y Footer.

5.5 — Configurar rutas en la aplicación
-----------------------------------------------------------------
  En `src/App.tsx`:
    Configura <BrowserRouter> y <Routes> para enlazar:
      - "/"        → <Landing /> (landing page)
      - "/register" → <Register /> (portal de registro de investigadores)
